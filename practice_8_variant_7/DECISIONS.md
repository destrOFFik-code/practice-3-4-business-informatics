# Решения

1. Статус изменяется только доменными методами `BusinessTrip`. Каждый метод сначала проверяет исходное состояние, затем данные операции и только после успешных проверок меняет поля. Общего setter статуса нет. Поэтому невозможно пропустить согласование, завершить командировку раньше срока или получить REJECTED без достаточной причины. Минимальная длина варианта 7 хранится в одной константе `MIN_REJECTION_REASON_LENGTH = 40`.

2. Текущую дату предоставляет `BusinessTripService` через внедряемый `Clock`. Приложение использует московский часовой пояс, тесты — фиксированное время. Модель принимает дату параметром `complete(LocalDate today)`, поэтому правила не зависят от даты запуска самопроверки. Сервис также хранит уникальные id и добавляет новую заявку из CSV только после успешной первой операции.
